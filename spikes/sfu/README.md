# Spike #7: прототип SFU на pion с simulcast

Одноразовый прототип для [Issue #7](https://github.com/balfag/dnd-vtt/issues/7). **Не** часть основного приложения и не попадает в корневой `go test ./...` (свой `go.mod`). Выводы — в [REPORT.md](REPORT.md).

## Запуск

```powershell
cd spikes/sfu
go build -o sfu.exe .
./sfu.exe                 # http://localhost:7777
./sfu.exe -tls            # https://<ip>:7777, самоподписанный сертификат
```

Откройте страницу в нескольких вкладках, введите имя, нажмите «Войти». У каждой чужой плитки кнопки `q`/`h`/`f` переключают simulcast-слой (240×135 / 480×270 / 960×540 при камере 960×540).

Для вкладок без камеры: Chrome/Edge с `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`. Если `getUserMedia` недоступен (нет устройств или небезопасный контекст), страница сама берёт тестовый поток (canvas + осциллятор); принудительно — `?synthetic=1`. `?auto=1&name=X` входит без клика.

## Флаги

| Флаг | По умолчанию | Назначение |
|------|--------------|------------|
| `-http` | `:7777` | адрес HTTP(S): страница, `/ws`, `/stats` |
| `-udp-port` | `7778` | единственный UDP-порт для ICE и медиа (ICE UDP mux) |
| `-tls` | выкл. | HTTPS/WSS на том же порту; сертификат ECDSA P-256 генерируется при старте в памяти (SAN: `localhost`, `127.0.0.1`, все IPv4 интерфейсов), на диск не пишется, действует 7 суток |
| `-rewrite` | вкл. | пересчёт seq/timestamp при смене слоя (выключать только для эксперимента, см. отчёт) |

`GET /stats` отдаёт `{"bytesIn":…,"bytesOut":…}` — байты RTP (payload + 12) на входе и выходе SFU; нужен для замеров.

## Сигнализация

WebSocket `/ws`, JSON-сообщения с полем `type`. Реализация WebSocket — своя, на стандартной библиотеке (допустимы только зависимости pion).

Клиент → сервер:

| type | поля | смысл |
|------|------|-------|
| `join` | `name` | первое сообщение |
| `offer` | `sdp` | **первый** offer клиента: его публикуемые треки (видео с 3 simulcast-слоями + аудио, `sendonly`) |
| `answer` | `sdp` | ответ на offer сервера |
| `candidate` | `candidate` | ICE-кандидат (trickle) |
| `layer` | `peer`, `layer` (`q`/`h`/`f`) | какой слой чужого участника слать мне |
| `leave` | | выход |

Сервер → клиент:

| type | поля | смысл |
|------|------|-------|
| `joined` | `id`, `peers[{id,name}]` | клиент принят, список уже находящихся в комнате |
| `peer-joined` / `peer-left` | `id`, `name` | вход/выход участника |
| `offer` | `sdp` | перенегоциация: добавлены/удалены чужие треки |
| `answer` | `sdp` | ответ на первый offer клиента |
| `candidate` | `candidate` | ICE-кандидат сервера |
| `layer-switched` | `peer`, `layer` | слой для этого получателя фактически переключён |

Порядок: `join` → `joined` → клиент шлёт `offer` → сервер `answer` → сервер сразу шлёт `offer` с чужими треками → клиент `answer`. Дальше **всегда инициирует сервер** (при входе/выходе других); клиент после первого offer новых offer не создаёт, поэтому glare невозможен. Сервер не шлёт offer, пока предыдущий не получил answer (при накоплении изменений — один следующий offer).

Чужие треки приходят с `stream.id` = id участника.

## Файлы

- `main.go` — флаги, HTTP, настройка pion (VP8 + Opus, интерцепторы по умолчанию, UDP mux), самоподписанный сертификат
- `room.go` — комната, участники, сигнализация, подписки, перенегоциация
- `forward.go` — пересылка RTP, выбор слоя, пересчёт seq/timestamp, детектор ключевого кадра VP8
- `ws.go` — минимальный WebSocket-сервер
- `index.html` — клиент (вшит через `embed`)
