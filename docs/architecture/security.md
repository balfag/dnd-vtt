# Безопасность и доступ

> Статус: `review`. Решение: [ADR-0008](../adr/0008-accounts-and-game-sessions.md)

## Модель угроз (кратко)

Сервер открыт в интернет на домашнем ПК мастера. Угрозы:
1. Посторонний нашёл адрес и пытается войти. → Вход только по аккаунту; регистрация только по действующей ссылке на игру; защита от перебора.
2. Игрок пытается увидеть секреты мастера (GM-слой, вики, скрытые броски). → Фильтрация на сервере.
3. Игрок пытается сломать состояние или ПК мастера (загрузка файлов, path traversal, флуд). → Валидация, лимиты, изоляция путей.
4. Чужой сайт пытается действовать от имени вошедшего пользователя (CSRF, cross-site WebSocket). → `SameSite`, проверка `Origin`.
5. Перехват трафика. → HTTPS/WSS при подключении извне, DTLS-SRTP для медиа (встроено в WebRTC).

## Аккаунты и вход

Модель и сценарии — в [ADR-0008](../adr/0008-accounts-and-game-sessions.md). Здесь — правила, которые проверяет сервер.

### Мастер
- Аккаунт мастера ровно один (`account.is_gm = 1`), создаётся на первом запуске через `/setup`.
- `/setup` и `POST /api/setup` работают, только пока аккаунта мастера нет, и только с loopback-адреса (`127.0.0.0/8`, `::1`). Нужен одноразовый setup-токен из URL, который сервер генерирует при старте и держит в памяти.
- При каждом запуске сервер генерирует одноразовый GM-токен (в памяти, живёт 10 минут) и открывает браузер на `http://localhost:<port>/?gm=<token>`. Клиент обменивает его на сессию входа (`POST /api/auth/gm-token`). Принимается только с loopback.
- С любого адреса мастер входит логином и паролем (`POST /api/auth/login`) в любое время.

### Игрок
- Войти или зарегистрироваться игрок может **только с действующей ссылкой на игру**: в запросе передаётся токен ссылки, сервер проверяет, что игровая сессия активна.
- Регистрация создаёт аккаунт и участника кампании. Логин занят → `409 conflict`.
- Вход без ссылки или по недействительной ссылке → `403` с кодом `no_active_game`. Участник удалён мастером → `403` с кодом `removed`.
- Сессия входа игрока привязана к игровой сессии; завершение или смена игровой сессии отзывает её.

### Сессии входа
- Cookie `dndvtt_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` — **только** если запрос пришёл по HTTPS. Без этого браузер не сохранит cookie при игре по `http://` в локальной сети.
- Значение — 32 байта из `crypto/rand` (base64url), в БД — `sha256` в hex.
- Срок: мастер — 30 дней с продлением (`last_seen_at` и `expires_at` обновляются не чаще раза в час); игрок — до конца игровой сессии, но не больше 24 часов.
- Выход (`POST /api/auth/logout`) удаляет сессию входа. Смена пароля отзывает все сессии входа аккаунта, кроме текущей; сброс пароля — все.
- Отзыв сессии закрывает её WebSocket-соединения (см. [protocol.md](protocol.md#закрытие-соединения)).

### Пароли
- argon2id, параметры и формат — в ADR-0008. Пароль не логируется и не возвращается в ответах.
- Логин 3–32 символа `[a-z0-9_.-]`, сравнивается в нижнем регистре; пароль 8–128 символов.
- Сброс пароля: мастер создаёт одноразовую ссылку `/reset/<token>` на 30 минут; использованная или просроченная ссылка не работает. Сбросить так пароль мастера нельзя — мастер восстанавливает доступ через GM-токен на своём ПК.

### Защита от перебора
- Неудачные попытки входа считаются в памяти: не больше 5 в минуту на пару (IP, логин) и 20 в минуту на IP. Превышение — `429 rate_limited` с `Retry-After`.
- Тот же лимит на IP — для регистрации, проверки ссылки на игру и сброса пароля.
- Неверный логин и неверный пароль дают одинаковый ответ `401 invalid_credentials`; при неизвестном логине всё равно вычисляется argon2id (по фиктивному хешу), чтобы время ответа не выдавало существование логина.

## CSRF и WebSocket

- Все изменяющие запросы — `POST`/`PUT`/`PATCH`/`DELETE` с телом JSON. Сервер отклоняет (`403 forbidden`) запрос, у которого заголовок `Origin` есть и не совпадает со схемой, хостом и портом самого запроса. Заголовкам `X-Forwarded-*` доверяем только от туннеля (решается в spike #8).
- WebSocket-рукопожатие `/ws` проверяет `Origin` так же и требует действующую сессию входа.

## Авторизация

| Ресурс | GM | Player |
|--------|----|--------|
| Кампании | создание, изменение, список | только кампания текущей игровой сессии |
| Игровые сессии и ссылка на игру | начать, завершить, сменить ссылку | нет |
| Участники | список, удаление, сброс пароля | список участников своей кампании (имя, цвет, онлайн) |
| Сцены: просмотр | все | только активная, без слоя `gm` |
| Фишки: видимость | все | кроме `hidden` и слоя `gm` |
| Фишки: перемещение | все | где он в `owners` и фишка не `locked` |
| Туман | редактирует | видит только раскрытое; маска применяется на сервере (скрытые фишки не отправляются) |
| Броски `gm` / `blind` | видит | `gm`: видит свои; `blind`: не видит результат |
| Личные сообщения | только где он автор или адресат | только где он автор или адресат |
| Фишки: своя (`owners`) | — | видна всегда, кроме слоя `gm`, даже `hidden` и в тумане |
| Вики | полный доступ | **нет доступа**: все запросы вики — `403` (показ — только через handout'ы) |
| Handout'ы | показывает во время игры | видит адресованные ему (всем или лично) |
| Листы | все | свой: чтение и запись; чужие: только публичная часть (имя, портрет) |
| Ассеты | загрузка, удаление, список | чтение только тех, что сейчас фон активной сцены или изображение видимой ему фишки или изображение handout'а, видимого ему в чате; остальные — `404` |

## Загрузка файлов

- Загружает только мастер (на старте). Лимит — 50 МиБ на файл; REST — [protocol.md](protocol.md#ассеты-m1).
- Проверка MIME по содержимому, а не по расширению; разрешены изображения (png, jpg, webp, gif) и аудио (позже).
- Имя на диске — sha256, исходное имя только в БД, поэтому path traversal невозможен.
- SVG запрещён (может содержать скрипты). Все ассеты отдаются с `Content-Security-Policy: sandbox` и `nosniff`.
- Размер изображения — не больше 16384 px по стороне (защита клиента от «бомб» распаковки).

## Содержимое вики и handout'ов

- Сервер принимает документ только по схеме вики v1 ([protocol.md](protocol.md#содержимое-страницы)): неизвестные узлы и метки отклоняются, неизвестные атрибуты отбрасываются. Ссылки — только `http`, `https`, `mailto`; изображения — только ассеты этой же кампании по `assetId` (без произвольных URL).
- Клиент показывает содержимое (в том числе handout у игрока) только через редактор с той же схемой в режиме чтения; сырой HTML не вставляется.
- Handout не раскрывает внутренности вики: упоминания и броски в нём запрещены, клиент мастера заменяет их текстом до отправки.

## Заголовки

Заголовки ставит сервер на **каждый** ответ (страницы, API, статика, WebSocket-рукопожатие); у ответов `GET /assets/{id}` — свой CSP `sandbox` (см. «Ассеты» в [protocol.md](protocol.md#ассеты-m1)), остальное — как ниже.

| Заголовок | Значение |
|-----------|----------|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self' ws: wss:; worker-src 'self' blob:; media-src 'self' blob:; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` |
| `Referrer-Policy` | `no-referrer` — токен ссылки на игру не должен утечь через `Referer` |
| `X-Content-Type-Options` | `nosniff` |
| `Permissions-Policy` | `camera=(self), microphone=(self), display-capture=(self), geolocation=(), payment=(), usb=()` |
| `Cross-Origin-Opener-Policy` | `same-origin` — выносные окна рабочей области открываются на том же источнике и продолжают работать |

Почему так:
- **Без внешних источников:** приложение работает без интернета, CDN запрещены ([CLAUDE.md](../../CLAUDE.md)); `'self'` хватает всему клиенту.
- **`'unsafe-inline'` только для стилей:** ProseMirror и dockview ставят атрибут `style` у элементов (ширины столбцов, размеры панелей); скрипты встраивать нельзя — `script-src 'self'` без `'unsafe-inline'` и `'unsafe-eval'`.
- **Без `'unsafe-eval'`:** PixiJS по умолчанию компилирует шейдерные функции через `new Function`; клиент подключает `pixi.js/unsafe-eval` — тот же движок без `eval`.
- **`blob:`** — изображения и воркеры, которые создают PixiJS и клиент (предпросмотр загрузки); **`data:`** — мелкие изображения в стилях.
- **`ws:`/`wss:`** — WebSocket того же хоста; в CSP3 `'self'` уже их покрывает, явные схемы — для браузеров, где это не так.
- **`frame-ancestors 'none'`** — приложение нельзя встроить во фрейм (защита от кликджекинга); выносные окна — это `window.open`, не фреймы.
- Нарушение политики в клиенте — ошибка: e2e-тесты падают на любом событии `securitypolicyviolation`.

## Секреты

Ключ TLS, токены туннеля, хеши паролей и токенов хранятся в папке данных с правами только для текущего пользователя и никогда не попадают в репозиторий и логи. Токены и пароли не пишутся в логи даже частично; пути `/play/<token>` и `/reset/<token>` логируются без токена.
