# Протокол клиент ↔ сервер

> Статус: `draft`

## Транспорт

- Одно WebSocket-соединение на вкладку: `wss://<host>/ws`.
- Аутентификация: токен сессии в cookie (`HttpOnly`, `SameSite=Strict`), получается при входе по инвайту (см. [security.md](security.md)).
- Формат: JSON-текстовые фреймы. Бинарные данные (ассеты) идут через REST (`POST /api/assets`), а не через WS.
- REST используется для загрузок, экспорта и инвайтов. Всё интерактивное идёт через WS.

## Конверт сообщения

```jsonc
{
  "t": "token.move",        // тип: <домен>.<действие>
  "id": "c-42",             // id запроса клиента (для ответа), опционально
  "re": "c-42",             // в ответе сервера — id запроса, на который отвечаем
  "seq": 1532,              // монотонный номер события сервера (только в событиях)
  "d": { ... }              // данные
}
```

- **Команда** (клиент → сервер): `t` + `id` + `d`.
- **Ответ** (сервер → клиент): `t: "ack"` или `t: "error"` с `re`.
- **Событие** (сервер → клиенты): `t` + `seq` + `d`. Рассылается только тем, кому разрешено видеть.

Ошибка: `{ "t": "error", "re": "c-42", "d": { "code": "forbidden", "message": "..." } }`.
Коды ошибок: `bad_request`, `forbidden`, `not_found`, `conflict`, `rate_limited`, `internal`.

## Синхронизация

1. После подключения клиент шлёт `session.hello {lastSeq?}`.
2. Сервер отвечает `session.snapshot` — полное состояние, видимое этому клиенту: кампания, активная сцена, фишки, игроки онлайн, последние N сообщений чата.
3. Далее приходят события с растущим `seq`.
4. При переподключении клиент шлёт `lastSeq`. Если сервер ещё хранит буфер событий с этого номера — досылает их, иначе отправляет новый снапшот.

**Оптимистичные обновления:** клиент сразу показывает перемещение своей фишки; при `error` откатывает изменение. Перетаскивание во время движения шлётся с троттлингом (около 20 Гц) как `token.drag` (не сохраняется в БД), финальная позиция — как `token.move` (сохраняется).

## Правила

- Сервер **всегда** проверяет права, клиентским проверкам не доверяем.
- Кубики бросает сервер (`crypto/rand`), клиент только отображает результат.
- Rate limit на соединение (например, 50 сообщений/с, на `token.drag` — 30/с).
- Типы сообщений описываются в общем месте: Go-структуры в `internal/ws/protocol` и генерация TS-типов в `web/src/shared/protocol` (генерация через `tygo` или вручную с тестом-сверкой — решить в M0).
