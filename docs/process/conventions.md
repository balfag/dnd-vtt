# Соглашения

## Общие
- Язык кода, комментариев, коммитов — английский. Документация — русский.
- Кодировка UTF-8, переводы строк LF (см. `.editorconfig`, `.gitattributes`).
- Комментарий объясняет **почему**, а не что. Публичные Go-идентификаторы — с doc-комментарием.

## Коммиты — Conventional Commits
```
<type>(<scope>): <summary in imperative, lower case, no period>

<body: why, not what>

Refs #12
```
- type: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`, `perf`, `spike`
- scope: `server`, `client`, `vtt`, `av`, `sheet`, `wiki`, `net`, `store`, `proto`, `deps`, `docs`
- Ломающее изменение протокола или схемы: `!` после scope и `BREAKING CHANGE:` в теле.

## Ветки
`<type>/<issue>-<short-slug>`: `feat/12-token-drag`, `fix/31-fog-leak`, `docs/5-protocol`.

## Go
- Форматирование `gofmt` / `goimports`, линтер `golangci-lint` (конфиг появится в M0).
- Пакеты в `internal/`, без глобального состояния; зависимости передаются через конструкторы.
- `context.Context` — первым параметром для всего, что делает I/O.
- Ошибки оборачиваются: `fmt.Errorf("load scene %s: %w", id, err)`. Без `panic` в обработчиках.
- Логирование — `log/slog`, структурированные поля, без секретов.
- Без CGO.

## TypeScript / React
- `strict: true`, без `any` (только в исключительных случаях и с комментарием).
- ESLint + Prettier (конфиг появится в M0).
- Структура по фичам: `web/src/features/<feature>/`.
- Функциональные компоненты и хуки. Глобальное состояние — Zustand, серверное состояние приходит из WS-событий.
- Никаких внешних CDN, шрифты и иконки — локально.

## i18n
- Все строки UI — через `t('feature.key')`. Ключи: `<feature>.<area>.<name>`, например `vtt.toolbar.ruler`.
- Файлы `web/src/i18n/ru.json` и `en.json` обновляются в одном PR. Отсутствие ключа в одном из языков роняет тест.
- Игровые термины переводятся по [glossary.md](../glossary.md).

## Протокол
- Новый тип сообщения добавляется сначала в [protocol.md](../architecture/protocol.md), затем в Go и TS.
- Имена: `<domain>.<action>`, данные в `camelCase`.

## Тесты
- Go: табличные юнит-тесты рядом с кодом (`*_test.go`); для БД — тесты на временной SQLite; для WS — интеграционные тесты с `httptest`.
- Обязательно покрыты: права доступа и фильтрация видимости, парсер кубиков, правила 5e, миграции.
- TS: Vitest для логики (store, протокол, утилиты); компоненты — по необходимости.
- E2E (Playwright) — начиная с M1 для ключевого сценария «мастер создал сцену → игрок вошёл → видит фишку».

## Зависимости
- Новая зависимость — указать в PR, зачем она и какая у неё лицензия. Проект под AGPL-3.0 ([ADR-0007](../adr/0007-license-agpl-3.md)), поэтому разрешены MIT, BSD, ISC, Apache-2.0, MPL-2.0, LGPL, GPL-3.0, AGPL-3.0. Запрещены GPL-2.0-only, SSPL, проприетарные и «non-commercial» лицензии.
- Крупная зависимость (фреймворк, движок) — через ADR.
