# Роли

В проекте три участника. Одновременно над кодом работает один агент.

| Роль | Кто | Отвечает за | Не делает |
|------|-----|-------------|-----------|
| **Владелец** | Пользователь | Приоритеты, ответы на вопросы, согласование спек и ADR, мердж PR | — |
| **Архитектор** | Сильная модель (Claude Opus) | Документация и ADR, декомпозиция на задачи, **бриф** (промт) на каждую задачу, **ревью** реализации | Не пишет продуктовый код (кроме исправлений по ходу ревью мелочей в 1–2 строки — и то только с согласия владельца) |
| **Исполнитель** | Более слабая модель | Реализация строго по брифу, тесты, PR | Не меняет спеки, ADR и протокол; не принимает архитектурных решений; не расширяет скоуп |

## Цикл задачи

```
Владелец ── идея ──► Архитектор: спека в docs/ ──► Владелец согласовал
                                   │
                                   ▼
               Архитектор: Issue + бриф (status:ready)
                                   │
                                   ▼
        Исполнитель: ветка → код → тесты → PR (status:in-review)
                                   │
                                   ▼
            Архитектор: ревью по review-checklist.md
               │                               │
         APPROVE ▼                     CHANGES ▼
    Владелец мерджит            бриф правок в PR (status:changes-requested)
                                               │
                                               └──► Исполнитель исправляет ──► снова ревью
```

## Статусы задачи (метки)

| Метка | Значение | Кто ставит |
|-------|----------|------------|
| `status:needs-spec` | Нет согласованной спеки или есть вопрос к владельцу | Архитектор |
| `status:needs-brief` | Спека есть, брифа ещё нет | Архитектор |
| `status:ready` | Бриф написан, исполнитель может брать | Архитектор |
| `status:in-review` | PR открыт, ждёт ревью архитектора | Исполнитель |
| `status:changes-requested` | Ревью нашло проблемы, есть бриф правок | Архитектор |
| `status:blocked` | Заблокировано внешней причиной | Любой |

После APPROVE архитектор снимает статусную метку и пишет владельцу, что PR готов к мерджу.

## Где что лежит

- **Бриф** — в теле GitHub Issue (раздел «Бриф для исполнителя»). Шаблон: [brief-template.md](brief-template.md).
- **Ревью** — комментарием в PR. Чек-лист: [review-checklist.md](review-checklist.md).
- **Правки после ревью** — в том же комментарии ревью, в формате мини-брифа (что, где, почему, как проверить).

## Как запустить исполнителя

Исполнителю достаточно одного сообщения:

```
Ты — исполнитель в проекте D:\dnd. Прочитай CLAUDE.md (раздел «Если ты исполнитель»),
затем выполни бриф из Issue #<N>: gh issue view <N>
```

Для правок после ревью:

```
Ты — исполнитель в проекте D:\dnd. Прочитай CLAUDE.md (раздел «Если ты исполнитель»).
Исправь PR #<M> по последнему ревью: gh pr view <M> --comments
```
