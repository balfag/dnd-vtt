# ADR-0002: встроенный SFU на pion/webrtc

- **Статус:** accepted
- **Дата:** 2026-10-15

## Контекст
6–8 участников с камерами у всех. P2P-mesh требует от каждого участника отправлять поток каждому (7 исходящих видеопотоков у каждого): для домашних каналов и слабых ПК это неприемлемо. Внешние медиасерверы противоречат автономности.

## Решение
- SFU внутри приложения мастера на **pion/webrtc v4** (`internal/av`).
- Один UDP-порт для всех (ICE UDP mux) + ICE-TCP фолбэк + встроенный TURN (**pion/turn**) для туннельного режима.
- Simulcast со стороны клиентов, выбор слоя на SFU под каждого получателя.
- Сигнализация — через основной WebSocket.

## Рассмотренные альтернативы
- **P2P mesh:** не масштабируется на 8 камер.
- **LiveKit server как sidecar-бинарник:** зрелый, но это второй процесс, свои порты и конфиг, усложняет упаковку. Остаётся запасным вариантом, если собственный SFU окажется слишком трудоёмким: решение фиксируем после spike в M0.
- **mediasoup:** требует Node и нативной сборки.

## Последствия
- Логика выбора simulcast-слоёв, обработка RTCP (PLI/NACK) и переподключения — на нас. Используем pion/interceptor.
- Исходящий канал мастера — главный ограничитель (см. docs/systems/voice-video.md).
