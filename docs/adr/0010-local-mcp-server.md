# ADR-0010: MCP-сервер для ИИ-ассистента мастера

- **Статус:** accepted
- **Дата:** 2026-10-16
- **Supersedes:** —

## Контекст
Владелец хочет, чтобы ИИ-ассистент (Claude Desktop и подобные клиенты MCP) мог делать всё то же, что мастер: готовить сцены, расставлять фишки, вести вики, создавать NPC, управлять игрой. Решено: в первой версии ассистент работает **на ПК мастера**; удалённый доступ — позже и отдельным решением.

## Решение
- MCP-сервер встроен в тот же бинарник, отдельного процесса или установки нет.
- Транспорт: **stdio** (`dndvtt mcp` — клиент MCP запускает его сам и общается через stdin/stdout; процесс подключается к уже запущенному приложению мастера по loopback) и **streamable HTTP** на `/mcp` только с loopback-адреса.
- Права ассистента = права мастера. Доступ даёт отдельный **токен MCP**, который мастер создаёт и отзывает в настройках; токен хранится хешем, как остальные токены ([security.md](../architecture/security.md)).
- Инструменты (tools) MCP — тонкая обёртка над теми же сервисами, что и REST/WebSocket (`internal/game`, `internal/wiki`, `internal/sheet`…): никакой отдельной логики и отдельных проверок прав.
- Изменения, сделанные ассистентом, видны всем как обычные изменения мастера и помечаются в логе («сделано ассистентом»).
- Библиотека — официальный Go SDK MCP (выбор версии и проверка лицензии — в брифе первой задачи).

## Рассмотренные альтернативы
- **Отдельный сервис MCP поверх REST:** лишний процесс и вторая копия моделей.
- **Доступ из интернета сразу:** нужен отдельный слой защиты (подтверждение действий, ограничения прав), откладываем.

## Последствия
- Каждый новый сервис проектируется так, чтобы его операции были пригодны и для REST, и для MCP (одни и те же функции сервиса).
- Опасные операции (удаление кампании, удаление участника) через MCP требуют подтверждения мастера в интерфейсе — уточняется в спеке [mcp-server.md](../systems/mcp-server.md).
