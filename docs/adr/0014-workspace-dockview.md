# ADR-0014: рабочая область на dockview

- **Статус:** accepted
- **Дата:** 2026-10-29
- **Supersedes:** —

## Контекст
Владелец хочет рабочую область мастера и игрока как в IDE: почти любую часть интерфейса (холст сцены, чат, бой, сцены, вики, позже видео и лист) можно открыть вкладкой, разделить экран на любые области, менять их размер перетаскиванием и вынести в отдельное окно браузера (второй монитор). Порядок внедрения владелец оставил архитектору.

Сейчас экран стола — фиксированная раскладка ([table-screen.md](../design/table-screen.md)): холст и правая панель 22rem со вкладками. Вики (M3) — первая система, которой нужны несколько одновременно открытых документов рядом со столом. Если ввести тайлинг после вики, придётся переделывать и стол, и вики, поэтому рабочая область — **первая задача M3**.

Нужно: вкладки, группы, разделение по любой стороне, изменение размеров, перетаскивание вкладок между группами, выносные окна, сохранение и восстановление раскладки, React 19, без CDN, лицензия совместима с AGPL-3.0.

## Решение
- **`dockview-react@8.5.1`** (MIT; React-обёртка над `dockview` → `dockview-core`, у которых нет других зависимостей) в `dependencies` клиента. Версия закрепляется точно; транзитивные `dockview` и `dockview-core` — через `pnpm.overrides` на ту же `8.5.1`.
- Рабочая область — один компонент `Workspace` на базе `DockviewReact`; содержимое панелей — обычные React-компоненты из каталога панелей ([workspace.md](../architecture/workspace.md)).
- **Выносное окно** — popout-группа dockview: окно `window.open` того же источника, содержимое рендерится порталом из основного окна. Поэтому у выносного окна **те же** store и WebSocket-соединение, второго подключения нет.
- Раскладка сохраняется сериализацией dockview (`toJSON`) в `localStorage` на устройстве, отдельно для каждого аккаунта, кампании и экрана. На сервер раскладка не попадает.
- Ниже 900 px ширины (как сейчас у стола) тайлинга нет: панели показываются вкладками разделов по одной на весь экран.

## Рассмотренные альтернативы
- **FlexLayout (`flexlayout-react`, MIT):** вкладки, разделение и выносные окна есть, но меньше сообщество, тема и API менее гибкие, версия 0.x.
- **react-mosaic (Apache-2.0):** только тайлинг без вкладок и выносных окон, тянет react-dnd и lodash.
- **Своя реализация на `react-resizable-panels`:** изменение размеров есть, а перетаскивание вкладок с подсветкой зон, выносные окна и сериализацию пришлось бы писать самим; это больше кода, чем вся раскладка стола.
- **Отдельная вкладка браузера на каждую панель со своим WebSocket:** проще технически, но N соединений на одного мастера, рассинхронизация выделения и инструментов между окнами, двойной расход канала.

## Последствия
- Бандл клиента растёт; точный прирост (gzip) исполнитель указывает в PR задачи рабочей области. Рабочая область нужна только на экранах стола и вики, поэтому грузится в их ленивых чанках.
- Экран стола переезжает в рабочую область: верхняя полоса и полоса инструментов остаются, холст и правая панель становятся панелями. Поведение M1 не меняется.
- **Холст сцены в M3 не выносится в отдельное окно:** перенос WebGL-холста PixiJS в другой документ не проверен, у панели холста выносное окно отключено. Снять ограничение — отдельной задачей после проверки.
- Выносное окно закрывается вместе с основным; если браузер заблокировал всплывающее окно, панель остаётся на месте, а пользователь видит подсказку.
- Тема dockview задаётся CSS-переменными из [visual-language.md](../design/visual-language.md); собственные стили dockview подключаются из пакета, не с CDN.
