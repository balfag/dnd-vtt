# ADR-0013: Playwright для e2e-тестов

- **Статус:** proposed
- **Дата:** 2026-10-16
- **Supersedes:** —

## Контекст
[conventions.md](../process/conventions.md) требует e2e с M1 для сценария «мастер создал сцену → игрок вошёл по ссылке → видит фишку → мастер двигает → игрок видит перемещение». Нужны два браузерных контекста одновременно (мастер и игрок с разными cookie), реальный бинарник с вшитым клиентом и запуск в CI на ubuntu.

## Решение
- **`@playwright/test@1.63.0`** (Apache-2.0) в `devDependencies` клиента; только Chromium.
- Тесты — в `web/e2e/`, конфиг — `web/playwright.config.ts`, запуск — `pnpm e2e`. Обычный `pnpm test` (Vitest) их не запускает.
- Сервер под тестом — **собранный бинарник** (`go build` с вшитым `web/dist`) в режиме `-dev` с временной папкой данных и свободным портом. Конфиг Playwright запускает его через `webServer`. Вход мастера — по GM-ссылке, которую бинарник печатает при старте.
- CI: отдельный job `E2E` на `ubuntu-latest` после job `Web`: `pnpm exec playwright install --with-deps chromium`, сборка бинарника, `pnpm e2e`. При падении job сохраняет трассировку Playwright как артефакт. Браузер скачивается только в CI и у разработчика. В клиент и бинарник ничего внешнего не попадает, правило «без CDN» не нарушается.
- Проверки опираются на доступные роли и тексты (`getByRole`, `getByText`) и на тестовые атрибуты `data-testid` только у холста. Пиксели холста не сравниваются.

## Рассмотренные альтернативы
- **Cypress:** один браузерный контекст на тест, два участника с разными cookie — неудобно; тяжелее в CI.
- **WebDriver/Selenium:** медленнее, больше настройки.
- **Только интеграционные тесты Go:** не проверяют клиент и вшивание сборки.

## Последствия
- CI дольше примерно на 2–3 минуты; браузер кэшируется в CI.
- На Windows у разработчика e2e запускается так же (`pnpm e2e`), но в CI — только ubuntu.
- Изменение `.github/workflows/ci.yml` делает исполнитель задачи #56 по брифу (это явное разрешение для той задачи).
