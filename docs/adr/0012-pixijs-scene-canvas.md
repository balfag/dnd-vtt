# ADR-0012: PixiJS для холста сцены

- **Статус:** proposed
- **Дата:** 2026-10-16
- **Supersedes:** —

## Контекст
Холст сцены (M1) рисует фон до 20000×20000 px, сетку, сотни фишек, туман, рисунки, шаблоны, пинги и линейку. Нужны панорама и зум без рывков на ноутбуке игрока, хит-тест для перетаскивания и одинаковая картинка в Chrome, Edge, Firefox и Safari. Стек в [overview.md](../architecture/overview.md) уже называет PixiJS v8, но решения по нему не было. По [conventions.md](../process/conventions.md) крупная зависимость оформляется ADR.

## Решение
- Холст — **`pixi.js@8.22.0`** (MIT): WebGL, при недоступности WebGL — WebGPU или запасной путь самой библиотеки. Версия закрепляется точно; обновление — отдельной задачей.
- **Без обёрток** вроде `@pixi/react`: React владеет интерфейсом вокруг холста, холст — одним компонентом с собственным классом сцены. Данные приходят из хранилища Zustand, обратно — только команды протокола.
- Слои холста повторяют слои протокола: фон (`map`), сетка, рисунки (`drawings`), фишки (`tokens`), у мастера `gm`, туман, интерфейс холста (линейка, пинги, выделение).
- Туман рисуется на клиенте по `fog.ops` (маска); у мастера — полупрозрачно. Безопасность от этого не зависит: скрытые фишки сервер не отправляет.
- Фон — текстура из `/assets/{id}`. Изображение больше предела текстуры видеокарты (`MAX_TEXTURE_SIZE`, обычно 8192–16384) режется на плитки при загрузке.
- Логика без рендера (координаты, сетка, клетки шаблонов, линейка с диагоналями 2024) — отдельные чистые модули с тестами Vitest. Рендер проверяется скриншотами по [skills/frontend.md](../../skills/frontend.md).

## Рассмотренные альтернативы
- **Canvas 2D своими руками:** просто, но панорама и зум на больших картах с сотнями объектов упираются в CPU, а хит-тест и пакетная отрисовка — это свой мини-движок.
- **Konva:** удобный API, но Canvas 2D под капотом — та же проблема производительности.
- **SVG:** прост для рисунков и тумана, но тысячи DOM-узлов и большие растры тормозят.
- **Three.js или Babylon:** избыточны для 2D, больше размер сборки.

## Последствия
- Размер клиента растёт примерно на 250–300 КБ gzip. Холст грузится лениво, только на экране стола, поэтому страницы входа остаются лёгкими.
- WebGL в CI недоступен: тесты логики — без рендера; e2e ([ADR-0013](0013-playwright-e2e.md)) проверяет состояние приложения, а не пиксели холста.
- Освещение и линия видимости (M6) ложатся на тот же рендер: фильтры и маски PixiJS.
