# ADR-0011: общая библиотека контента на GitHub

- **Статус:** proposed
- **Дата:** 2026-10-16
- **Supersedes:** —

## Контекст
Владелец хочет, чтобы мастера делились своими картами, ассетами, графикой и звуками через общий GitHub-репозиторий прямо из приложения, а мастер, подключивший свой GitHub, мог искать и скачивать из него контент. Решено: в библиотеку попадают только **собственные работы автора под CC-BY-4.0 или CC0**, публикация проходит **ревью мейнтейнеров** через pull request, тексты правил из закрытых книг запрещены.

## Решение
- Отдельный публичный репозиторий проекта (например, `dnd-vtt-library`), не основной репозиторий кода. Создаёт его владелец.
- Структура: один пакет — одна папка с манифестом (`manifest.json`: название, автор, лицензия CC-BY-4.0 или CC0, теги, тип — карта, ассет, набор фишек, звук, homebrew-пакет, превью) и файлами. Индекс пакетов строится CI репозитория.
- **Чтение** (поиск, скачивание) работает без входа в GitHub; вход нужен для **публикации**.
- **Публикация из приложения:** мастер подключает GitHub через **OAuth device flow** (вводит короткий код на github.com; в приложении не хранится секрет клиента). Приложение делает форк, коммит пакета и pull request; мастер в диалоге подтверждает, что это его работа и выбранная лицензия. Токен GitHub хранится в папке данных с правами только для текущего пользователя.
- **Ревью:** CI репозитория проверяет манифест, лицензию, типы и размеры файлов; мейнтейнеры проверяют содержимое. Принятый пакет становится доступен всем.
- **Большие файлы:** ограничение размера пакета; крупные файлы — через Git LFS или GitHub Releases (решается в спеке библиотеки).
- Функция **необязательная**: приложение полностью работает офлайн без неё.

## Рассмотренные альтернативы
- **Собственный сервер-хранилище:** нужен хостинг и модерация силами проекта, противоречит «без облака».
- **Свободная загрузка без ревью:** правовой риск для владельца репозитория (чужие работы, тексты закрытых книг).

## Последствия
- `vision.md`: не-цель «маркетплейс контента» уточняется — платного маркетплейса нет, бесплатная библиотека под CC — цель.
- Нужен документ с правилами публикации (что можно, лицензии, как оформить атрибуцию) и шаблон PR репозитория библиотеки.
- Homebrew-пакеты в библиотеке — только собственный контент автора; пересказ или копия текста закрытых книг отклоняется на ревью.
