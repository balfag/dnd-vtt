# ADR-0008: Локальные аккаунты и игровые сессии вместо инвайтов

- **Статус:** proposed
- **Дата:** 2026-10-15
- **Supersedes:** —

## Контекст

Первая версия спеки ([vision.md](../vision.md), [security.md](../architecture/security.md)) предполагала вход игрока по бессрочной инвайт-ссылке без регистрации: игрок идентифицируется только cookie в браузере. Владелец уточнил требования:

1. Игрок должен заходить со **своим персонажем с любого устройства** (ПК, ноутбук, планшет), а не только из браузера, где он впервые вошёл.
2. Мастер тоже должен входить **с другого устройства**, а не только с `localhost`.
3. Ссылка действует только на одну игровую встречу: когда мастер начинает новую, **старая ссылка перестаёт работать**.
4. Вне игровой встречи игрок не может войти вообще.
5. Электронной почты и внешних сервисов нет: сервер работает локально, иногда без интернета.

## Решение

### Сущности
- **Аккаунт** (`account`) — логин и пароль, хранятся в БД установки мастера. Это локальная учётная запись, не облачная: на другой установке её нет. Ровно один аккаунт на установку — аккаунт мастера (`is_gm`).
- **Участник** (`player`) — связь аккаунта с кампанией: имя в кампании, цвет, роль (`gm` | `player`), позже — персонаж. Участник сохраняется между игровыми сессиями.
- **Игровая сессия** (`game_session`) — одна игровая встреча в кампании, от «Начать игру» до «Завершить игру». В каждый момент на установке активна не больше одной.
- **Ссылка на игру** (game link) — `https://<host>/play/<token>`, создаётся при старте игровой сессии. Хранится только хеш токена. Ссылка работает, пока сессия активна; новая сессия или «Сменить ссылку» делают старую недействительной.
- **Сессия входа** (`login_session`) — вход на конкретном устройстве, cookie `dndvtt_session`. У игрока она привязана к игровой сессии и перестаёт действовать, когда та завершается. У мастера не привязана и живёт 30 дней с продлением при использовании.
- **Сброс пароля** (`password_reset`) — одноразовая ссылка `/reset/<token>` на 30 минут, которую мастер выдаёт игроку вручную.

Инвайты (`invite`) из первой версии спеки **не вводятся**: их роль выполняет ссылка на игру.

### Сценарии
- **Первый запуск.** Аккаунта мастера нет. Приложение открывает браузер на `http://localhost:7777/setup?t=<одноразовый токен>`; мастер задаёт логин и пароль. Страница настройки доступна только с loopback-адреса.
- **Вход мастера.** С любого устройства — логин и пароль на `/login`. На ПК мастера приложение при каждом запуске открывает `http://localhost:7777/?gm=<одноразовый токен>`, который сразу создаёт сессию входа мастера (только с loopback). Через этот же путь мастер, забывший пароль, входит на своём ПК и меняет пароль.
- **Начало игры.** Мастер выбирает кампанию и нажимает «Начать игру»: создаётся игровая сессия и ссылка на игру. Если была другая активная сессия, она завершается, её сессии входа игроков отзываются, их WebSocket-соединения закрываются.
- **Вход игрока.** Игрок открывает ссылку на игру и либо входит (логин + пароль), либо регистрируется (логин, пароль, имя в кампании). Регистрация возможна **только** по действующей ссылке на игру; открытой регистрации нет. Если игрок уже участник кампании, он продолжает тем же участником; если нет — участник создаётся.
- **Удаление игрока.** Мастер помечает участника удалённым: его сессии входа отзываются, по ссылке на игру он больше не войдёт в эту кампанию (вход сообщает «доступ закрыт мастером»).
- **Забыл пароль.** Мастер в списке участников нажимает «Сбросить пароль» и пересылает игроку одноразовую ссылку. Новый пароль отзывает все сессии входа этого аккаунта.
- **Вне игры.** Без активной игровой сессии игрок не может войти; `/login` для аккаунта без `is_gm` отвечает «игра сейчас не идёт».

### Технические решения
- Пароли — **argon2id** из `golang.org/x/crypto/argon2` (BSD-3-Clause, чистый Go), параметры `m=64 MiB, t=1, p=4`, соль 16 байт, ключ 32 байта, хранение в PHC-формате `$argon2id$v=19$m=65536,t=1,p=4$<salt>$<hash>`. Параметры читаются из строки при проверке, поэтому их можно менять без миграции.
- Все токены (сессии входа, ссылки на игру, сброс, одноразовые GM-токены) — 32 байта из `crypto/rand`, base64url без паддинга; в БД — только `sha256` в hex.
- Логин: 3–32 символа `[a-z0-9_.-]`, хранится в нижнем регистре, уникален. Пароль: от 8 до 128 символов, других требований нет.
- Защита от перебора: не больше 5 неудачных входов в минуту на пару (IP, логин) и 20 — на IP; превышение — `429` с `Retry-After`. Ответ на неверный логин и неверный пароль одинаковый.
- Детали cookie, CSRF и прав — в [security.md](../architecture/security.md), схема — в [data-model.md](../architecture/data-model.md), REST-API — в [protocol.md](../architecture/protocol.md).

## Рассмотренные альтернативы
- **Бессрочный инвайт + cookie без пароля** (первая версия): не переносится между устройствами, нельзя войти мастеру извне.
- **Персональная ссылка-ключ без пароля** для каждого игрока: переносится между устройствами, но утёкшая ссылка — это полный доступ навсегда, и нет способа «закрыть» старую игру, не перевыпуская ссылки всем.
- **Внешний вход (OAuth: Discord, Google):** требует интернет, регистрации приложения у провайдера и публичного redirect-адреса; противоречит офлайн-работе.
- **Сброс пароля по почте:** нет почтового сервера и интернета не всегда.
- **bcrypt** вместо argon2id: тоже приемлем, но ограничивает пароль 72 байтами; argon2id — рекомендация OWASP и RFC 9106.

## Последствия
- `vision.md` меняется: вход без регистрации заменяется входом по аккаунту; в не-целях остаются только облачные аккаунты.
- Новая прямая зависимость `golang.org/x/crypto`. Её актуальные версии требуют Go 1.26, поэтому минимальная версия Go проекта поднимается до 1.26.
- В M0 добавляются: первый запуск мастера, кампании (создание и список), игровые сессии, вход и регистрация, страницы `/setup`, `/login`, `/play/<token>`, `/reset/<token>`. Задача #5 делится на несколько Issues.
- Игроку нужно запомнить пароль, это лишний шаг по сравнению с инвайтом. Компенсируется тем, что регистрация совмещена с первым входом по ссылке.
- Один мастер на установку. Со-мастер и наблюдатель — позже, отдельным решением.
