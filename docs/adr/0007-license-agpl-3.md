# ADR-0007: лицензия проекта — AGPL-3.0

- **Статус:** accepted
- **Дата:** 2026-10-15

## Контекст
Пользователь хочет лицензию, которая обязывает других делиться изменениями, но не ограничивает его самого. Приложение — сетевой сервер: игроки пользуются им через браузер, а копию программы не получают.

## Решение
- Код проекта распространяется под **GNU AGPL-3.0-or-later** (`LICENSE`).
- Правообладатель — автор проекта. Сам правообладатель лицензией не связан: может использовать код как угодно, в том числе выпустить его под другой (например, коммерческой) лицензией.
- Игровой контент SRD 5.2 остаётся под CC-BY-4.0 с атрибуцией в `NOTICE`.

## Рассмотренные альтернативы
- **GPL-3.0:** обязывает раскрывать изменения только при распространении бинарника. Тот, кто поднял изменённую версию как сервис для игроков, мог бы не делиться кодом. AGPL закрывает эту лазейку (раздел 13).
- **MPL-2.0:** слабый копилефт на уровне файлов, позволяет встраивать код в закрытый продукт.
- **MIT/Apache-2.0:** никого ни к чему не обязывают.

## Последствия
- Любой, кто изменит программу и даст к ней доступ по сети, обязан предоставить пользователям исходный код своей версии. В UI нужна ссылка на исходники (раздел «О программе»), это задача M5.
- **Внешние контрибьюторы:** их код тоже попадает под AGPL, и без их согласия правообладатель не сможет перелицензировать проект целиком. Если сторонние PR появятся, до первого такого мерджа нужно ввести CLA (соглашение о передаче прав или о праве перелицензирования).
- Зависимости должны быть совместимы с AGPL-3.0: MIT, BSD, ISC, Apache-2.0, MPL-2.0, LGPL, GPL-3.0. Нельзя: GPL-2.0-only, проприетарные, SSPL.
- В Go-файлах и TS-файлах не обязательно ставить заголовок лицензии; достаточно файла `LICENSE` в корне и SPDX-идентификатора `AGPL-3.0-or-later` в `go.mod`-комментарии или `web/package.json` (`"license"`).
