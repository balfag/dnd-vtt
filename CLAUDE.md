# CLAUDE.md — правила для агентов

Этот файл обязателен к прочтению в начале **каждой** сессии. Он короткий специально: подробности лежат в `docs/`, здесь только то, что нельзя пропустить.

## Проект за 30 секунд

Автономное приложение для D&D-сессий онлайн. Мастер запускает один `.exe` (Go), игроки заходят по ссылке из браузера (клиент на TypeScript/React вшит в бинарник). Четыре системы: виртуальный стол, голос и видео (встроенный SFU), лист персонажа (D&D 5e 2024 / SRD 5.2), вики мастера.

Видение: [docs/vision.md](docs/vision.md) · Архитектура: [docs/architecture/overview.md](docs/architecture/overview.md) · Роадмап: [docs/roadmap.md](docs/roadmap.md)

## Язык

- Документация, Issues, описания PR — **на русском**.
- Код, идентификаторы, комментарии в коде, сообщения коммитов, имена веток — **на английском**.
- Строки интерфейса — только через i18n-ключи (`ru` по умолчанию, плюс `en`), никакого захардкоженного текста в компонентах.
- Термины берём из [docs/glossary.md](docs/glossary.md). Новый термин сначала добавляем туда.

## Режим работы: один агент за раз

Над проектом одновременно работает **один** агент. Параллельных веток от разных агентов нет, поэтому:
- работай в одной ветке на одну задачу;
- перед началом убедись, что `main` свежий и нет чужой незавершённой ветки (`git branch -a`, открытые PR). Если есть — спроси пользователя, продолжать её или нет.

## Цикл задачи (кратко)

Полная версия: [docs/process/workflow.md](docs/process/workflow.md).

1. **Контекст.** Прочитай этот файл, [docs/roadmap.md](docs/roadmap.md), документ нужной системы в `docs/systems/` и связанные ADR в `docs/adr/`.
2. **Задача.** Одна GitHub Issue из текущего майлстоуна с меткой `status:ready`. Если GitHub недоступен — задачу формулирует пользователь в чате.
3. **Спека раньше кода.** Если задача меняет поведение, протокол, модель данных или архитектуру — сначала обнови документ в `docs/` (или добавь ADR) в той же ветке. Если спеки не хватает, **не придумывай**: поставь `status:needs-spec` и задай вопрос.
4. **Ветка.** `<type>/<issue>-<slug>`, например `feat/12-token-drag`. Типы: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `spike`.
5. **Коммиты.** [Conventional Commits](https://www.conventionalcommits.org/) на английском, в теле `Refs #12`. Мелкие осмысленные коммиты.
6. **Проверки.** Перед PR проходит всё из [docs/process/definition-of-done.md](docs/process/definition-of-done.md).
7. **PR.** По шаблону `.github/PULL_REQUEST_TEMPLATE.md`. Мерджит **пользователь** (squash). Агент не мерджит сам.
8. **Завершение.** Отметь чек-лист в Issue; если сдвинулся план — обнови `docs/roadmap.md`.

## Жёсткие запреты

- Не пушить напрямую в `main`, не делать force-push в `main`, не переписывать опубликованную историю.
- Не коммитить секреты, токены, `.env`, пользовательские данные из `data/`.
- Не редактировать по существу ADR со статусом `accepted`. Решение меняется только новым ADR с полем `Supersedes`.
- Не добавлять игровой контент не из SRD 5.2 (никаких текстов из PHB/MM/DMG и других закрытых книг): это лицензионный риск.
- Не добавлять зависимость с CGO на сервере (сборка должна оставаться `CGO_ENABLED=0`).
- Не тянуть внешние CDN в клиент: приложение должно работать без интернета (кроме туннеля и STUN).
- Не создавать GitHub-репозитории, метки или релизы и не публиковать что-либо без явного согласия пользователя.
- Не добавлять зависимости с лицензией, несовместимой с AGPL-3.0 (см. [ADR-0007](docs/adr/0007-license-agpl-3.md)). Не мерджить сторонние PR, пока не введено CLA.

NOTICE                  атрибуция SRD 5.2
docs/
  vision.md             продукт, роли, сценарии, не-цели

  roadmap.md            майлстоуны и их состав

```

internal/               серверные пакеты Go (server, ws, game, av, wiki, sheet, store, net)
web/                    клиент: React + Vite + TypeScript
```

## Когда сомневаешься

Спроси пользователя. Задать вопрос дешевле, чем переделывать. Особенно это касается листа персонажа: детальные требования к нему пользователь ещё не дал.
